## ⚠ 배포별 URL은 로그인이 걸린다
`vercel deploy` 가 출력하는 **배포별 URL** (`hongjuhyung-<해시>-stuls.vercel.app`) 은 Vercel Authentication 때문에 익명 요청에 **302 → `vercel.com/sso-api`** 로 응답한다. 이 주소를 제출하면 BRA-C13(로그인 없이 열림)에서 탈락한다.
제출·공유는 **반드시 별칭 주소 `https://hongjuhyung.vercel.app`** 를 쓴다.

## GitHub 자동 배포
GitHub 저장소 `stulss/bra-portfolio`의 `master` 브랜치를 기존 Vercel 프로젝트 `hongjuhyung`에 연결한다. `vercel.json`은 커밋된 `preview/`를 공개 폴더로 지정한다. 검토 후보인 `preview/candidates.json`은 로컬과 제출 ZIP에는 남지만 Git 추적 및 Vercel 업로드에서 제외되므로 공개되지 않는다.

```bash
vercel git connect https://github.com/stulss/bra-portfolio.git --yes
git push origin master
```

노션 자료를 갱신한 뒤에는 로컬에서 `python build.py --input input --output preview`, `python test_build.py`, `python package.py`를 실행하고 생성된 `preview/`까지 커밋한다. Vercel 빌드 환경에는 노션 토큰을 올리지 않으며, 공개 후보 파일도 배포하지 않는다.

## CLI 수동 재배포 방법
프로젝트 링크(`projectId`)가 `tmp/hongjuhyung/.vercel/` 안에만 있으면, 그 폴더를 지우고 다시 배포할 때 **새 프로젝트가 만들어져 URL이 바뀐다.** 그래서 링크를 `bra-portfolio/.vercel-project.json` 에 따로 보관한다. (프로젝트·조직 ID일 뿐 토큰이 아니다.)

검토용 초안 재배포 — `bra-portfolio/` 에서:

```bash
python build.py --output tmp/hongjuhyung && rm -f tmp/hongjuhyung/candidates.json && mkdir -p tmp/hongjuhyung/.vercel && cp .vercel-project.json tmp/hongjuhyung/.vercel/project.json && cd tmp/hongjuhyung && vercel deploy --prod --yes
```

## 최종 공개 배포 (작성자 확인 후)
`build.py --publish` 는 아래가 전부 충족돼야 통과한다. 이 게이트는 약화시키지 않는다.
- `profile.json` 의 `human_lines_confirmed` · `privacy_reviewed` · `facts_reviewed` 가 모두 `true`
- `headline` 이 "한 사람" 으로 끝나고 `app_due` 가 채워져 있음
- `story` 의 모든 장면이 `approved: true`

통과하면 배너가 사라지고 `candidates.json` 도 생성되지 않는다. 최종 배포 후 지원 문서 PDF를 다시 출력하고, 새 시크릿 창에서 위 표의 5개 주소를 다시 확인한다.
